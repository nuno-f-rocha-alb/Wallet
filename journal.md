# Wallet — build journal

One `§N` per built unit (flow handoff + audit trail). Newest last.

## §1 — Phase 0: foundation & deploy skeleton

**What**: Monorepo (`shared`/`server`/`web`), Fastify serving `/api` + the installable
PWA from one container, SQLite via built-in `node:sqlite`, migration runner,
Authelia-aware multi-user auth, Dockerfile + compose.

**Decisions / root causes**
- **`node:sqlite` over `better-sqlite3`**: local Node is v25; native prebuilds lag, and
  the built-in has zero compile cost and works identically in the container. Loaded via
  `createRequire` so Vite/vitest don't try to statically resolve this newer builtin
  (that was the cause of the initial `Failed to load url sqlite` test error).
- **Auth = trust Authelia, don't rebuild it**: identity comes from a configurable
  forwarded header, honored **only** when the peer IP ∈ `TRUSTED_PROXIES` (anti-spoof).
  First user bootstraps admin; per-user bearer token for VPN/PWA. No passwords in-app.
- **Multi-user from day 0**: `users` table + `user_id` will scope every domain row
  (Phase 1+). Sharing/household deferred.
- **Inlined migrations** (TS array, not `.sql` files) so nothing extra to copy into the
  image. WAL mode; `closeDb()` wired to Fastify `onClose` (fixes Windows temp-file EPERM
  on test teardown).
- **Icons** generated by a tiny dep-free PNG encoder (`scripts/make-icons.mjs`).

**Gate**: typecheck ✓ · lint ✓ · vitest 3/3 ✓ · build ✓ · `docker compose build` ✓ ·
`docker compose up` healthy ✓. Live-verify in-container: health 200; alice→id1 admin,
bob→id2 non-admin (isolated); no-auth→401; PWA root 200; **persisted across container
restart** (alice still id1). CodeRabbit: see `reviews/wallet.md`.
